# Google Sheets セットアップ手順
## フルフル 商品マスタ取材フォーム — 社長向け初回設定ガイド

所要時間：5〜10 分。Google アカウントにログインできる状態でお読みください。

---

## 必要なもの

- Google アカウント（フルフルの業務用を推奨）
- このファイルと同じフォルダにある `apps-script.gs` のコード

---

## ステップ 1：Google スプレッドシートを新規作成する

1. ブラウザで [https://sheets.google.com](https://sheets.google.com) を開く
2. 「新しいスプレッドシート」（＋ボタン）をクリックして新規作成
3. 左上のタイトル部分（「無題のスプレッドシート」）をクリックして、  
   名前を `フルフル 商品マスタ` に変更する（任意・わかりやすい名前ならなんでもOK）

> シートの列見出しはスクリプトが自動で挿入するので、手入力は不要です。

---

## ステップ 2：Apps Script エディタを開く

1. スプレッドシートのメニューから **拡張機能** → **Apps Script** をクリック
2. 新しいタブで「Apps Script エディタ」が開く
3. 左側のファイル一覧に `コード.gs` が表示されている

---

## ステップ 3：スクリプトを貼り付けて保存する

1. `コード.gs` の中身（`function myFunction() { }` の部分）を**全て選択して削除**する
2. この手順書と同じフォルダにある **`apps-script.gs`** ファイルを開く
3. そのファイルの中身を**全てコピー**する
4. Apps Script エディタに**貼り付ける**
5. `Ctrl+S`（Mac は `Cmd+S`）で保存する

---

## ステップ 4：ウェブアプリとしてデプロイする

1. 右上の **「デプロイ」** ボタン →「**新しいデプロイ**」をクリック
2. 「種類を選択」の歯車アイコン → **「ウェブアプリ」** を選択
3. 以下の設定にする：

   | 項目 | 設定値 |
   |---|---|
   | 説明 | フルフル取材フォーム（任意） |
   | 次のユーザーとして実行 | **自分（〇〇@gmail.com）** |
   | アクセスできるユーザー | **全員** |

4. **「デプロイ」** をクリック
5. 「アクセスを承認」ダイアログが出たら：
   - 自分の Google アカウントを選択
   - 「このアプリは確認されていません」と表示されたら「詳細」→「〇〇（安全でないページ）に移動」→「許可」
   - これは**自分で作ったスクリプトを自分で承認**しているだけです（安全です）

---

## ステップ 5：発行された URL を config.js に貼る

1. デプロイ完了画面に **「ウェブアプリのURL」** が表示される（`https://script.google.com/macros/s/.../exec` で始まる）
2. この URL をコピーする
3. 取材フォームのフォルダ（`interview-app/`）にある **`config.js`** をテキストエディタで開く
4. 以下の行を見つける：
   ```
   const APPS_SCRIPT_URL = "";
   ```
5. `""` の中に URL を貼り付ける：
   ```
   const APPS_SCRIPT_URL = "https://script.google.com/macros/s/（長いID）/exec";
   ```
6. 保存する

---

## 動作確認

1. `interview-app/index.html` をブラウザで開く
2. 商品を選んで回答者名を入れ、「はじめる」→ 質問に適当に答えて「完了」まで進む
3. 「Google Sheetsへ送信」ボタンを押す
4. スプレッドシートを開いて「取材回答」シートにデータが追加されていればOK

---

## よくある問題

### 「このアプリは確認されていません」と出た

→ 自分で作ったスクリプトを Google が自動確認するには審査申請が必要ですが、
社内用ツールでは不要です。「詳細」→「〇〇（安全でないページ）に移動」→「許可」で進めてください。

### デプロイ後に URL を更新したい

→ Apps Script エディタで **「デプロイ」→「デプロイを管理」** を開き、
既存のデプロイを選んで「編集」→「バージョン = 新バージョン」にして「デプロイ」を押します。
URL は変わりません（同じ URL のまま最新コードが反映されます）。

### スプレッドシートにデータが入らない

1. `config.js` の URL が `""` のままになっていないか確認
2. ブラウザのデベロッパーツール（F12）→ Console タブを開いて、エラーが出ていないか確認
3. 「送信できませんでした」と出た場合は、「本文をコピー」→ メール等で送信してください

## 将来の拡張（原価・写真列を追加するときの方法）

取材回答シートに列を追加したい場合は、`apps-script.gs` の先頭にある
`ANSWER_HEADERS` 配列に列名を追記し、再デプロイしてください。

Webアプリ（フォーム）側に追加データを渡したい場合は、
`js/data.js` の `QUESTIONS` 配列に質問を追加し、
`js/submit.js` の `buildPayload()` 関数に対応するキーを追加します。

> **開発者への引き継ぎメモ**（ファイルパスは `interview-app/` を起点）：
> - 質問の追加・変更: `js/data.js`
> - 送信データの変換: `js/submit.js` → `buildPayload()`
> - シート列の定義: `sheets-setup/apps-script.gs` → `ANSWER_HEADERS` / `COST_HEADERS`

## 送信の成否を確実に確認したいとき（強く推奨）

Webアプリの送信は仕様上、フォーム側では「送信できた／できなかった」の確定判定ができません（no-cors制約による opaque response）。フォームに「送信完了」と出ても、実際は Sheet に入っていない場合を検知できないため、**Apps Script 側で受信通知メールを送る**設定を推奨します。

### 手順

1. `apps-script.gs` の末尾にある `notifyReceived_(payload)` 関数のコメントを外して有効化する
2. 関数内の `TO = "運用担当のメールアドレス@example.com"` を実際の宛先に書き換える
3. `doPost` 関数内、`sheet.appendRow(row)` の直後（`try` の最後・`catch` の前）に次の1行を追加：
   ```javascript
   notifyReceived_(payload);
   ```
4. 保存→「デプロイ」→「デプロイの管理」→ 既存デプロイの右の鉛筆アイコン→「バージョン」を「新しいバージョン」→デプロイ

### 送信上限

Apps Script の `MailApp.sendEmail` は 1日あたりの送信上限があります（個人アカウント=100通/日、Google Workspace=1500通/日）。運用上は十分な余裕です。
